# Security audit notes — GeniaFirewall 0.6.3

## Что усилено

### Fail-closed Pending

`FirewallAccess.Ask` в standalone WFP Normal преобразуется в app-specific WFP BLOCK. `Позже`, закрытие окна и `Не напоминать` не дают приложению сетевой доступ.

### True Del без fail-open

Удаление строки больше не обязано означать удаление защитного состояния. При safe Del скрытая runtime-запись остаётся частью WFP policy как `Ask`. Это предотвращает открытие сети только из-за очистки UI.

### Подавление повторных prompt

Сессионное подавление связано с EXE, PID и временем запуска процесса, а не только с PID. Это снижает риск ошибочного подавления после повторного использования PID Windows.

### Portable import

Runtime quarantine не считается переносимым доказательством доверия и не экспортируется как постоянное правило. Trusted System evidence по-прежнему перепроверяется локально.

## Остаточные риски

1. **Первоначальное обнаружение остаётся post-connect.** Новый неизвестный процесс может выполнить ограниченный обмен до того, как watcher увидит его и UI поставит WFP Ask-block.
2. **Нет inbound backend.** 0.6.3 самостоятельно контролирует outbound TCP/UDP IPv4/IPv6.
3. **UI всё ещё участвует в обнаружении неизвестных приложений.** Для истинного pre-connect Ask нужен WFP callout driver/service path, не зависящий от UI polling.
4. **Локализация не является security boundary.** Все policy decisions должны опираться только на enum/path/hash/signature/service identity, а не на отображаемые строки.
5. **Hidden quarantine хранится локально.** Повреждение локальных settings должно приводить к диагностируемому fail-safe поведению; резервные копии данных остаются обязательными.

## Рекомендация тестирования

До перехода к callout driver необходимо подтвердить:

- Del на разрешённом EXE мгновенно оставляет сеть заблокированной;
- строка исчезает и появляется снова только при новой активности;
- `Позже/X` не создают повторный prompt в рамках того же запуска;
- после полного завершения процесса новый запуск снова может запросить решение;
- `Не напоминать` сохраняет WFP Block и переживает перезапуск UI;
- Allow/Block снимают Pending suppression;
- Service restart восстанавливает policy.
