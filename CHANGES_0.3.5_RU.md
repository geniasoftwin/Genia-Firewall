# GeniaFirewall 0.3.5 — изменения

## Сетевые запросы без popup-шторма

- Одновременные TCP/UDP события одного EXE собираются в один запрос с коротким debounce-окном.
- В одном prompt показывается до 20 уникальных назначений/локальных UDP-портов текущего burst.
- Network watcher больше не теряет разные TCP endpoint одного процесса в одном цикле сканирования.

## Временное разрешение

В prompt у кнопки «Разрешить» появился выбор области:

- **Всегда** — обычное постоянное Allow.
- **На 10 минут** — правило автоматически удаляется, запись возвращается в «Спрашивать».
- **До закрытия** — правило привязано к PID и пути EXE; при завершении именно этого экземпляра процесса правило удаляется.

PID-правила не переживают перезапуск GeniaFirewall: это сделано намеренно из-за возможного повторного использования PID. Временные правила из импортированной конфигурации также не становятся постоянными разрешениями.

## Hostname / reverse DNS

- Для TCP destination GeniaFirewall по возможности выполняет reverse DNS и показывает `hostname (IP):port`.
- Результаты кэшируются; неудачные запросы тоже имеют короткий negative-cache.
- Lookup имеет жёсткий timeout и не блокирует network watcher.
- Reverse DNS можно отключить в настройках.
- Hostname служит только для отображения: текущее правило Windows Firewall остаётся правилом приложения, а не правилом домена.
