# GeniaFirewall 0.6.2 — изменения

## Immediate Quarantine

0.6.2 закрывает найденное при тестировании окно после `Del` для уже запущенного приложения.

В режиме **Normal + GeniaFirewall WFP**, если включена настройка **«Немедленный WFP-карантин при Del для запущенного приложения»**, клавиша `Del` больше не снимает фильтр у работающего EXE. Вместо этого старое решение Allow/Block забывается и запись атомарно переводится в `Ask`.

Для WFP backend `Ask` означает `ASK-BLOCK`, поэтому сеть приложения блокируется до открытия/закрытия окна решения и остаётся заблокированной при выборе `Позже` или закрытии окна крестиком.

Если EXE не запущен, `Del` по-прежнему удаляет запись и её правило.

## UX

- Контекстное действие переименовано в **«Забыть решение / удалить»**.
- Для работающего EXE окно решения ставится в очередь сразу после успешного применения WFP-карантина — ждать следующего прохода watcher-а не нужно.
- Диагностика показывает состояние настройки `Del quarantine`.

## Совместимость

- UI / Service / Protocol: `0.6.2.0`.
- IPC protocol: `v5` (`GeniaFirewall.Service.v5`), чтобы UI 0.6.2 не подключался к старой службе 0.6.1.
- WFP backend остаётся outbound-only: TCP/UDP, IPv4/IPv6.
- Это всё ещё не kernel pre-connect Ask для абсолютно нового EXE. Такой режим требует WFP callout driver.
