# GeniaFirewall 0.6.3 — архитектура

## Цель релиза

0.6.3 не меняет проверенный standalone outbound WFP enforcement из 0.6.2. Релиз разделяет **видимую запись приложения** и **защитное состояние WFP**, улучшает Pending/Ask UX и добавляет русско-английскую локализацию.

## Локализация

UI использует `LocalizationService` и WPF `ResourceDictionary`:

- `Resources/Strings.ru-RU.xaml`
- `Resources/Strings.en-US.xaml`

Режимы: `Auto`, `Russian`, `English`. В `Auto` русский выбирается для русской Windows UI culture, в остальных случаях — English. В JSON сохраняются стабильные enum-значения, а не локализованный текст правил.

## Pending / Ask

В `Normal + GeniaFirewall WFP` приложение со статусом `Ask` соответствует fail-closed политике: Service устанавливает WFP BLOCK для EXE. Статус в UI — **«Ожидает решения» / “Pending decision”**.

`Позже` или закрытие prompt крестиком:

1. не превращает решение в постоянный `Block`;
2. оставляет `Ask` и WFP quarantine;
3. блокирует сеть;
4. подавляет повторный prompt для уже запущенного экземпляра процесса;
5. после полного завершения этого запуска приложение может спросить снова при следующем запуске.

Опция **«Не напоминать об этом приложении»** сохраняется в записи и запрещает автоматические prompt до ручного вызова «Показать запрос сейчас» или изменения настройки.

## True Del + скрытый quarantine

При включённом safe Del, в `Normal + GeniaFirewall WFP` удаление строки работающего/известного приложения выполняется так:

1. запись действительно исчезает из `Applications`;
2. в локальных settings создаётся `RuntimeQuarantineEntry` с EXE path и стабильным ID;
3. при построении WFP policy скрытая запись добавляется как `Ask`;
4. следовательно, удаление строки не открывает сеть;
5. при следующей обнаруженной сетевой активности скрытая запись материализуется обратно в список как `Ожидает решения`.

`RuntimeQuarantines` сохраняются локально, но не переносятся как portable policy при экспорте конфигурации.

## Quick Rules

Контекстное меню подготавливает модель быстрых профилей:

- EnableAll / Allow;
- OutgoingOnly;
- DisableAll / Block;
- IncomingOnly — видимо, но отключено до реализации inbound backend.

В 0.6.3 backend остаётся outbound-only, поэтому `Allow` и `OutgoingOnly` имеют одинаковый WFP outbound эффект. Полное различение направлений будет включено вместе с inbound WFP.

## Service / IPC

- Product version: `0.6.3.0`
- Pipe: `GeniaFirewall.Service.v6`
- Protocol: `6`
- WFP provider/sublayer и persistent policy сохраняют архитектуру 0.6.x.

После перехода с 0.6.2 службу необходимо переустановить из папки 0.6.3, чтобы UI и Service использовали один IPC protocol.

## Ограничение безопасности

Watcher остаётся user-mode механизмом обнаружения. Совершенно новый EXE теоретически может успеть выполнить начальный сетевой обмен до первого обнаружения. После обнаружения `Ask` блокируется WFP. Абсолютный pre-connect Ask без первого пакета требует WFP callout driver и остаётся следующим крупным этапом.
