# Изменения GeniaFirewall 0.6.1

## Secure Prompt Quarantine

- В самостоятельном `GeniaFirewall WFP` backend режим `Нормальный` теперь переводит впервые обнаруженное неизвестное приложение в состояние `Ask` и немедленно отправляет обновлённую policy в `GeniaFirewall.Service`.
- Для `Ask` служба создаёт четыре временных app-specific WFP `BLOCK`-фильтра: IPv4/TCP, IPv4/UDP, IPv6/TCP, IPv6/UDP.
- Блок ставится до SHA-256/Authenticode проверки и до открытия окна решения, поэтому уже обнаруженное приложение не продолжает пользоваться сетью за открытым prompt.
- `Разрешить` заменяет ASK-BLOCK на WFP `PERMIT`; `Блокировать` — на обычный WFP `BLOCK`; `Позже` оставляет приложение в карантине.
- Временное разрешение после истечения снова переводится в `Ask`, что в WFP Normal автоматически возвращает quarantine-блок.

## Скорость обнаружения

- Период polling watcher уменьшен с 1,25 с до 500 мс.
- Окно группировки нескольких назначений одного EXE уменьшено с 650 мс до 250 мс.
- При этом группировка до 20 сетевых событий на один запрос сохранена.

## Диагностика и UI

- `Ask` теперь отображается как `Ожидает решения`.
- Диагностика службы показывает отдельный счётчик `ask/quarantine`.
- Добавлена строка `Secure Prompt Quarantine` в диагностику UI.
- Текст prompt и настроек поясняет, что WFP Normal держит неизвестное приложение в карантине после его обнаружения.

## IPC / версии

- IPC protocol: v4 (`GeniaFirewall.Service.v4`).
- UI / Service / Protocol / manifest: `0.6.1.0`.

## Важное ограничение

0.6.1 существенно уменьшает окно утечки и полностью закрывает доступ после обнаружения неизвестного приложения, но не является настоящим pre-connect Ask. User-mode watcher всё ещё узнаёт о сетевой активности постфактум, поэтому очень короткий первоначальный обмен до первого обнаружения теоретически возможен. Полное устранение этого окна планируется через WFP callout driver.
