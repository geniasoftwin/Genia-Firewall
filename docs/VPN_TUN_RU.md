# VPN, TUN и LAN: совместимость

[English](VPN_TUN.md) · [Руководство тестировщика](../TESTING_RU.md)

VPN/TUN может создавать виртуальные интерфейсы и менять маршруты. Поведение правил до запуска, при работе и после остановки туннеля может отличаться.

App-level правила собственного **WFP backend не должны зависеть от индекса физического интерфейса**. Default physical inbound boundary в Normal настраивается отдельно. Эти механизмы проверялись на сценариях GeniaProxy/GeniaLink, но **универсальная совместимость со всеми VPN, TUN-драйверами, сетями и сторонними WFP-продуктами не гарантирована**.

## Контрольный A/B-тест

1. Тестируйте при локальном доступе к ПК, а не только через RDP/VPN.
2. Запишите версию Windows, backend, глобальный режим, профиль приложения, версию VPN/TUN и адаптер.
3. Включите **GeniaFirewall WFP + Нормальный**. Проверьте работу **без** туннеля.
4. Включите туннель, дождитесь интерфейса/маршрутов и повторите тест. При необходимости проверьте DNS, TCP, UDP, LAN.
5. Отключите и подключите туннель снова; по возможности проверьте sleep/resume и reboot.
6. Сравнивайте с отключённым GeniaFirewall **только на некритичном тестовом ПК**, потом возвращайте защиту.
7. Сохраните релевантные WFP BLOCK-события с временем и обезличенными адресами.

## LAN в обе стороны

Обнаружение устройства может работать по UDP, а передача — по TCP. Профиль **Только исходящие** на принимающем ПК не открывает inbound; для двустороннего LAN-приложения задайте **Разрешить всё** с обеих сторон.

~~~powershell
Test-NetConnection <IP-соседа> -Port <слушающий-TCP-порт>
~~~

Проверьте TCP **в обоих направлениях**, затем реальную передачу. Успешный TCP-тест сам по себе не проверяет UDP discovery или авторизацию приложения.

| Симптом | Что смотреть |
| --- | --- |
| UDP discovery работает, TCP передача нет | Inbound-профиль, listener, TCP-порт назначения |
| Global Allow all работает, Normal нет | App profile, matched WFP rule, default inbound block |
| VPN включился, но DNS/UDP нет | Профиль VPN-программы, маршруты, DNS, WFP BLOCK |
| Compatibility не исправил inbound | Его app-правила только исходящие |
| После смены backend связь не восстановилась | Cleanup GeniaFirewall и другие WFP providers |
