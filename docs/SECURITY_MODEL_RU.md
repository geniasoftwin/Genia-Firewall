# Модель безопасности GeniaFirewall и ограничения

[English](SECURITY_MODEL.md) · [Приватная отправка уязвимостей](../SECURITY.md)

Здесь описаны **архитектурные меры защиты**, а не сертификат безопасности или гарантия отсутствия обходов.

## Границы доверия

- **Portable UI:** решения пользователя, настройки, сведения о программах и локальная диагностика.
- **GeniaFirewall.Service (LocalSystem):** привилегированное управление WFP; UI общается со службой через авторизованный локальный IPC.
- **Windows WFP/BFE:** фактически применяет фильтры; важны layer, action, weight и направление.
- **Другие WFP providers:** могут влиять на итоговую сетевую политику.

## Защитные механизмы, особенно для 0.7.4 RC

- Встроенная служба устанавливается под защищённый Program Files, а не работает из writable portable-папки.
- SHA-256 для embedded/installed service, защищённые ACL файла и объекта SCM.
- Проверка service path, LocalSystem, зависимости BFE, параметров запуска и IPC identity.
- Транзакционное обновление службы с защищённым rollback предыдущей версии.
- Dynamic WFP runtime session и проверяемый cleanup при отключении WFP/backend.
- Контроль fingerprint/изменения EXE программы: подменённый или обновлённый файл не должен молча наследовать доверие.

Эти особенности lifecycle RC3 нельзя автоматически приравнивать к ручному установщику 0.7.3 Stable.

## Приватность и целостность

Программа не содержит developer analytics и не отправляет логи автоматически. Portable-правила и UI-журналы локальны, служебные данные — в `%ProgramData%\GeniaFirewall`. Необязательный reverse DNS обращается к DNS resolver Windows и может раскрыть ему запрашиваемый адрес.

**SHA-256 не подтверждает издателя.** 0.7.4 RC остаётся тестовой, пока UI и служба не будут подписаны Authenticode и не пройдены release gates. См. [политику подписи](../CODE_SIGNING_POLICY.md).

## Ограничения

- Нет собственного kernel callout driver и гарантированного kernel-held pre-connect Ask.
- Windows Firewall Compatibility не даёт полную двунаправленную WFP-семантику app-правил.
- Ошибочные правила могут разорвать RDP, LAN, DNS, VPN/TUN и другой важный трафик.
- Об уязвимостях сообщайте **приватно** через [SECURITY.md](../SECURITY.md). Не публикуйте эксплойты, ключи и чувствительные логи в Issues.
