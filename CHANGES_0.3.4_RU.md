# GeniaFirewall 0.3.4 — изменения

## Версия / запуск

- Embedded Windows manifest: `assemblyIdentity version="0.3.4.0"`.
- `.csproj`: `Version`, `AssemblyVersion`, `FileVersion` = `0.3.4.0`.
- UI/release name: `0.3.4`.
- `publish-portable.cmd` перед публикацией проверяет четырёхкомпонентную версию, очищает `bin`, `obj` и старую папку publish.

## Доверенные системные процессы

Новый режим включён по умолчанию и может быть отключён в Настройках или из tray-меню.

Авто-разрешение без popup выдаётся только если одновременно выполнены проверки:

1. EXE находится непосредственно в `%WINDIR%\\System32`.
2. Authenticode успешно проходит Windows `WinVerifyTrust`.
3. Издатель подписи идентифицируется как Microsoft.
4. EXE входит в минимальный встроенный allow-list.
5. Для `svchost.exe` дополнительно перечисляются Win32-службы текущего PID; **все** найденные службы должны входить в allow-list. Пустой, смешанный или неизвестный набор служб не получает автодоверие.
6. Перед фиксацией auto-allow должен быть успешно сохранён SHA-256 текущего EXE.

Текущий консервативный service allow-list: `Dhcp`, `Dnscache`, `NlaSvc`, `W32Time`, `BITS`, `wuauserv`, `UsoSvc`, `DoSvc`, `CryptSvc`.

Текущий direct EXE allow-list: `MoUsoCoreWorker.exe`, `UsoClient.exe`, `wuauclt.exe`, `SIHClient.exe`.

## UI / журнал

- Новая сортируемая колонка `Доверие`.
- Авто-доверенные строки: `🛡 Система` + статус `Авто-разрешено`.
- Tooltip и свойства показывают причину доверия.
- В строке состояния/сводке учитывается число системных доверенных записей.
- Поиск также ищет по издателю и причине доверия.
- В tray добавлен переключатель `Доверять системным компонентам Windows`.

## Поведение после обновления Windows

Если SHA-256 ранее доверенного системного EXE изменился, GeniaFirewall использует текущий PID, повторно проверяет подпись и service identity. При успехе новый SHA-256 фиксируется и auto-allow сохраняется. При неуспехе системная метка снимается и используется обычный путь карантина/запроса.

## Portable/import

Метка `Trusted System` считается локальным runtime-доказательством. При импорте JSON она снимается и не переносится как доказательство доверия на другую машину/сессию; само явно импортированное решение Allow/Block остаётся политикой пользователя.
